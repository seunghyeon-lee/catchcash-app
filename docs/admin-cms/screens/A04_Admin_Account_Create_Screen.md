## 2. 화면 개요

관리자 계정 등록 화면은 super_admin이 캐치캐쉬 CMS에 접근할 신규 관리자 계정을 직접 생성하는 화면이다.

이 화면에서는 관리자 이름, 이메일, 초기 비밀번호, 역할, 계정 초기 상태를 입력한다.  
계정 등록 전 확인 팝업을 통해 입력 정보를 다시 확인하고, 등록 완료 후 관리자 계정 목록 또는 상세 화면으로 이동한다.

중요:

```txt
관리자 계정 등록은 super_admin만 가능하다.
operator와 viewer는 접근할 수 없다.
관리자 초대 링크는 MVP 범위에서 제외한다.
관리자 셀프 회원가입은 제공하지 않는다.
등록 시 입력한 비밀번호는 서버에서 해시 처리하며 원문을 저장하지 않는다.
역할과 계정 상태는 생성 시점부터 접근 권한에 즉시 반영된다.
```

---

## 3. 화면 목적

### 3.1 관리자 목적

- 신규 CMS 관리자를 등록한다.
- 신규 관리자의 로그인 이메일과 초기 비밀번호를 설정한다.
- 신규 관리자의 역할을 지정한다.
- 계정을 즉시 활성화할지, 비활성 상태로 생성할지 결정한다.
- 등록 전 최종 확인을 거쳐 오등록을 방지한다.

### 3.2 시스템 목적

- CMS 접근 계정을 super_admin 통제하에 생성한다.
- 관리자 role 기반 권한 정책을 계정 생성 시점에 적용한다.
- 관리자 계정 생성 행위를 민감 운영 로그로 기록한다.
- 비밀번호 보안 정책을 서버에서 검증한다.

## 11. 역할 및 권한 영역

## 11.1 역할 선택 방식

와이어프레임 기준 radio button 형태로 역할을 선택한다.

```txt
역할
super_admin
operator
viewer
```

---

## 11.2 역할 옵션

| 역할 | 설명 |
|---|---|
| super_admin | 전체 접근 및 위험 액션 수행 가능 |
| operator | 일반 운영 액션 수행, 보안·관리자 로그 제한 |
| viewer | 조회 전용, 생성·수정·삭제 액션 제한 |

### 화면 문구 예시

```txt
역할을 선택하면 해당 역할에 메뉴 접근 범위와 액션 권한이 적용됩니다.
```

---

## 11.3 기본 선택값

MVP 권장:

```txt
기본 선택 없음
```

역할은 필수 선택으로 두고, super_admin을 실수로 생성하지 않도록 기본값을 두지 않는다.

## 12. 계정 초기 상태 영역

## 16. 저장 처리

## 16.1 성공 처리

등록 성공 시:

```txt
관리자 계정 생성
비밀번호 해시 저장
role 저장
status 저장
created_by_admin_id 저장
created_at 저장
민감 운영 로그 기록
```

성공 후 이동:

```txt
기본 권장: /admin/admins
선택 가능: /admin/admins/{adminId}
```

MVP에서는 목록으로 이동을 권장한다.

---

## 16.2 실패 처리

| 실패 사유 | 처리 |
|---|---|
| 이메일 중복 | 이메일 필드 오류 표시 |
| 비밀번호 정책 불충족 | 비밀번호 영역 오류 표시 |
| 권한 없음 | A24 접근 권한 부족 화면 |
| 서버 오류 | 저장 실패 팝업 또는 토스트 |
| 네트워크 오류 | 재시도 안내 |

## 17. 데이터 모델

## 17.1 Admin Role

```ts
type AdminRole =
  | 'super_admin'
  | 'operator'
  | 'viewer';
```

---

## 17.2 Admin Status

```ts
type AdminStatus =
  | 'active'
  | 'inactive'
  | 'locked';
```

등록 화면에서 선택 가능한 상태는 아래 2개다.

```txt
active
inactive
```

`locked`는 로그인 실패 횟수 초과 등 시스템 상태로만 사용하고 등록 시 선택하지 않는다.

---

## 17.3 Create Admin Request

```ts
type CreateAdminAccountRequest = {
  name: string;
  email: string;
  password: string;
  role: AdminRole;
  status: 'active' | 'inactive';
};
```

---

## 17.4 Create Admin Response

```ts
type CreateAdminAccountResponse = {
  admin_id: string;
  name: string;
  email: string;
  role: AdminRole;
  status: 'active' | 'inactive';
  created_at: string;
};
```

비밀번호 원문은 응답에 포함하지 않는다.

## 18. API 연동 기준

## 18.1 관리자 계정 생성

```txt
POST /api/admin/admins
```

### Request Body

```ts
{
  name: string;
  email: string;
  password: string;
  role: 'super_admin' | 'operator' | 'viewer';
  status: 'active' | 'inactive';

```

권한:

```txt
super_admin only

이메일 입력 필드 하단
```

## 19.4 접근 권한 없음

operator 또는 viewer가 접근한 경우 A24 접근 권한 부족 화면으로 이동한다.

## 20. 보안 정책

```txt
관리자 계정 등록 API는 super_admin만 호출할 수 있다.
서버에서 role을 반드시 재검증한다.
비밀번호 원문은 저장하지 않는다.
비밀번호는 서버에서 안전하게 해시 처리한다.
비밀번호 원문은 API 응답에 포함하지 않는다.
관리자 계정 생성은 민감 운영 로그로 기록한다.
super_admin 역할 생성 시 확인 팝업에서 역할을 명확히 표시한다.
관리자 초대 링크는 MVP에서 제공하지 않는다.
관리자 셀프 가입은 제공하지 않는다.
```

## 21. 운영 로그 정책

관리자 계정 등록 성공 시 민감 운영 로그를 남긴다.

| 항목 | 기록 |
|---|---|
| 액션 | `admin_created` |
| 실행자 | 현재 super_admin |
| 대상 | 생성된 관리자 계정 |
| 역할 | 생성된 role |
| 상태 | 생성된 status |
| 결과 | success / failed |
| 시각 | created_at |

비밀번호 원문은 로그에 남기지 않는다.

## 23. QA 체크리스트

## 23.1 권한

- [ ] super_admin은 관리자 계정 등록 화면에 접근할 수 있다.
- [ ] operator는 접근할 수 없다.
- [ ] viewer는 접근할 수 없다.
- [ ] operator/viewer 직접 URL 접근 시 A24로 이동한다.
- [ ] 생성 API는 서버에서 super_admin 권한을 재검증한다.

## 23.2 입력 검증

- [ ] 이름은 필수다.
- [ ] 이메일은 필수다.
- [ ] 이메일 형식을 검증한다.
- [ ] 중복 이메일은 등록할 수 없다.
- [ ] 비밀번호는 필수다.
- [ ] 비밀번호 확인은 필수다.
- [ ] 비밀번호와 비밀번호 확인이 일치해야 한다.
- [ ] 비밀번호는 8자 이상, 영문·숫자·특수문자를 포함해야 한다.
- [ ] 역할은 필수 선택이다.
- [ ] 초기 상태는 필수 선택이다.

## 23.3 등록 확인 팝업

- [ ] 계정 등록 클릭 시 확인 팝업이 열린다.
- [ ] 팝업에서 취소하면 입력 화면으로 돌아간다.
- [ ] 팝업에서 등록하면 생성 API를 호출한다.
- [ ] 비밀번호는 팝업에 표시하지 않는다.

## 23.4 저장 결과

- [ ] 저장 성공 시 관리자 계정 목록으로 이동한다.
- [ ] 저장 성공 시 민감 운영 로그가 기록된다.
- [ ] 저장 실패 시 오류 안내가 표시된다.
- [ ] 저장 실패 시 입력값이 유지된다.
