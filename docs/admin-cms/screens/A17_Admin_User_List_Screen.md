## 2. 화면 개요

유저 목록 화면은 캐치캐쉬 앱에 가입한 사용자 정보를 관리자 CMS에서 조회하는 화면이다.

관리자는 닉네임, 유저 ID, 로그인 제공자, 계정 상태, 가입일, 최근 활동, 획득 수, 문의 수를 기준으로 유저를 확인할 수 있다.

이 화면은 유저를 직접 수정하는 화면이 아니다.  
유저 정지와 해제는 `A18_Admin_User_Detail_Screen`에서 super_admin만 수행한다.

중요:

```txt
MVP 관리자 CMS에서는 사용자 이메일을 표시하지 않는다.
쿠폰 번호와 바코드를 표시하지 않는다.
유저 목록에서는 정지/해제 액션을 직접 수행하지 않는다.
유저 상세 화면으로 이동해 상세 정보와 관련 이력을 확인한다.
```

---

## 3. 화면 목적

### 3.1 관리자 목적

- 앱 사용자 목록을 조회한다.
- 상태별 사용자를 빠르게 필터링한다.
- 최근 활동이 있는 사용자를 확인한다.
- 보상 획득 수와 문의 수를 기반으로 이슈 가능 사용자를 파악한다.
- 특정 사용자의 상세 화면으로 이동한다.

### 3.2 시스템 목적

- 사용자 이메일 없이 운영에 필요한 식별 정보를 제공한다.
- 사용자 상태를 기준으로 관리자 액션 권한을 분리한다.
- 유저 상세, 보상 목록, 문의 목록과 연결되는 진입점을 제공한다.

## 5. 권한 정책

| 기능 | super_admin | operator | viewer |
|---|---:|---:|---:|
| 유저 목록 조회 | O | O | O |
| 유저 검색·필터 | O | O | O |
| 유저 상세 이동 | O | O | O |
| CSV 내보내기 | O | O | X |
| 유저 정지·해제 | A18에서 가능 | X | X |
| 내부 메모 작성 | A18에서 가능 | A18에서 가능 | X |
| 사용자 이메일 조회 | X | X | X |
| 쿠폰 번호·바코드 조회 | X | X | X |

viewer는 조회 전용 역할이므로 목록과 상세 조회만 가능하다.  
CSV 내보내기는 운영 데이터 반출 성격이 있으므로 MVP에서는 super_admin과 operator에게만 허용한다.

## 6. 화면 구조

와이어프레임 기준 화면 구성은 아래 순서로 확정한다.

```txt
AdminLayout
→ 상단 헤더
→ 화면 타이틀
→ 우측 CSV 내보내기 버튼
→ 필터 영역
→ 유저 목록 테이블
→ 페이지네이션
→ 하단 유저 상세 이동 버튼
```

## 7. UI 구성 요소

## 7.1 AdminLayout

### 구성

```txt
좌측 사이드바
상단 헤더
본문 콘텐츠 영역
```

### 사이드바 메뉴

현재 로그인한 관리자 role 기준으로 허용된 메뉴만 표시한다.

```txt
대시보드
보물상자
상품
매칭
보상
유저
문의
운영 로그
보안 로그
관리자
```

operator는 보안 로그와 관리자 메뉴를 보지 않는다.  
viewer는 운영 로그, 보안 로그, 관리자 메뉴를 보지 않는다.

## 7.2 상단 헤더

| 요소 | 설명 |
|---|---|
| 검색 입력 | 전역 검색 또는 현재 화면 검색 |
| 권한 표시 | 현재 관리자 role 표시 |

상단 검색과 본문 검색이 모두 있을 경우, 본문 검색은 유저 목록 검색에 우선 사용한다.

## 8. 필터 영역

## 8.1 필터 구성

| 필터 | 타입 | 설명 |
|---|---|---|
| 검색어 | text input | 닉네임, 유저 ID, 로그인 제공자 검색 |
| 상태 | select | 사용자 상태 |
| 가입 기간 | date range 또는 select | 가입일 기준 기간 |
| 최근 활동 | select | 최근 활동 시점 기준 |
| 정렬 | select | 목록 정렬 기준 |

### 검색 placeholder

```txt
닉네임 · 유저 ID · 로그인 제공자 검색
```

---

## 8.2 상태 필터

| 라벨 | 값 | 설명 |
|---|---|---|
| 전체 | `all` | 전체 사용자 |
| 활성 | `active` | 정상 이용 가능 사용자 |
| 정지 | `suspended` | 서비스 이용 제한 사용자 |
| 탈퇴 | `deleted` | 탈퇴 또는 삭제 처리 사용자 |
| 비활성 | `inactive` | 비활성 사용자, 필요 시 P1 |

MVP에서는 최소 `active`, `suspended`를 우선 지원한다.

---

## 8.3 가입 기간 필터

| 옵션 | 값 |
|---|---|
| 전체 | `all` |
| 오늘 | `today` |
| 최근 7일 | `last_7_days` |
| 최근 30일 | `last_30_days` |
| 직접 선택 | `custom` |

직접 선택을 지원할 경우 시작일과 종료일을 입력받는다.

---

## 8.4 최근 활동 필터

| 옵션 | 값 |
|---|---|
| 전체 | `all` |
| 오늘 활동 | `today` |
| 최근 7일 활동 | `last_7_days` |
| 최근 30일 활동 | `last_30_days` |
| 30일 이상 미활동 | `inactive_over_30_days` |

최근 활동 기준은 `last_active_at`을 사용한다.

---

## 8.5 정렬 옵션

| 라벨 | 값 |
|---|---|
| 최근 가입순 | `joined_desc` |
| 오래된 가입순 | `joined_asc` |
| 최근 활동순 | `last_active_desc` |
| 획득 수 많은 순 | `claim_count_desc` |
| 문의 수 많은 순 | `inquiry_count_desc` |

기본 정렬은 `joined_desc` 또는 `last_active_desc` 중 하나로 한다.  
MVP에서는 운영 확인 목적상 `last_active_desc`를 권장한다.

## 9. 테이블 정의

## 9.1 테이블 컬럼

| 순서 | 컬럼 | 예시 | 설명 |
|---:|---|---|---|
| 1 | 닉네임 | `보물헌터01` | 사용자가 설정한 닉네임 |
| 2 | 유저 ID | `USR-1024` | 내부 사용자 식별자 |
| 3 | 로그인 제공자 | `kakao` | Google, Kakao, Apple 등 |
| 4 | 상태 | `active` | 사용자 계정 상태 |
| 5 | 가입일 | `2025-07-01` | 서비스 가입일 |
| 6 | 최근 활동 | `2025-07-26 14:22` | 마지막 활동 시각 |
| 7 | 획득 수 | `12` | 보상 또는 보물 획득 수 |
| 8 | 문의 수 | `3` | 사용자가 등록한 문의 수 |

```txt
사용자 이메일
전화번호
소셜 계정 원문 식별자
쿠폰 번호

정확한 현재 위치 좌표
```

## 9.3 행 클릭 동작

|---|---|

## 14.4 접근 권한 없음

유저 목록은 viewer까지 접근 가능하므로 일반적으로 접근 권한 없음 상태가 발생하지 않는다.  
다만 권한 정보가 없거나 서버 검증에서 실패하면 A24 접근 권한 부족 화면으로 이동한다.

## 15. 보안 정책

```txt
사용자 이메일은 관리자 CMS에서 수집·조회·표시하지 않는다.
사용자 전화번호를 표시하지 않는다.
소셜 로그인 provider의 access token, refresh token을 표시하지 않는다.
쿠폰 번호와 바코드는 표시하지 않는다.
정확한 현재 위치 좌표는 목록에 표시하지 않는다.
CSV에도 민감 정보를 포함하지 않는다.
위험 액션은 목록에서 직접 제공하지 않는다.
유저 정지와 해제는 A18 상세 화면에서 super_admin만 수행한다.
```

## 16. 운영 로그 정책

아래 액션은 운영 로그로 남기는 것을 권장한다.

| 액션 | 로그 유형 |
|---|---|

CSV 내보내기는 데이터 반출 성격이 있으므로 요청자, 필터 조건, 시각을 기록한다.

## 17. 와이어프레임 반영 기준

현재 와이어프레임에서 확인된 요소를 아래처럼 반영한다.

| 검색 필드 | 유지 |
| 상태 필터 | 유지 |
| 가입 기간 필터 | 유지 |
| 최근 활동 필터 | 유지 |

## 18. QA 체크리스트

## 18.1 권한

- [ ] super_admin은 유저 목록을 조회할 수 있다.
- [ ] operator는 유저 목록을 조회할 수 있다.
- [ ] viewer는 유저 목록을 조회할 수 있다.
- [ ] viewer에게 CSV 내보내기 버튼은 보이지 않는다.
- [ ] 유저 정지/해제 버튼은 목록 화면에 표시되지 않는다.

## 18.2 검색·필터

- [ ] 닉네임으로 검색할 수 있다.
- [ ] 유저 ID로 검색할 수 있다.
- [ ] 로그인 제공자로 검색할 수 있다.
- [ ] 상태 필터가 정상 동작한다.
- [ ] 가입 기간 필터가 정상 동작한다.
- [ ] 최근 활동 필터가 정상 동작한다.
- [ ] 정렬 옵션이 정상 동작한다.
- [ ] 필터 초기화 시 기본 목록으로 돌아간다.

## 18.3 테이블

- [ ] 닉네임이 표시된다.
- [ ] 유저 ID가 표시된다.
- [ ] 로그인 제공자가 표시된다.
- [ ] 상태가 배지로 표시된다.
- [ ] 가입일이 표시된다.
- [ ] 최근 활동 시각이 표시된다.
- [ ] 획득 수가 표시된다.
- [ ] 문의 수가 표시된다.
- [ ] 사용자 이메일은 표시되지 않는다.
- [ ] 쿠폰 번호와 바코드는 표시되지 않는다.

## 18.4 이동

- [ ] 유저 행 선택 후 유저 상세 버튼을 누르면 A18로 이동한다.
- [ ] 선택된 유저가 없으면 유저 상세 버튼은 비활성화된다.
- [ ] 획득 수 클릭 시 보상 목록 userId 필터로 이동 가능하다.
- [ ] 문의 수 클릭 시 문의 목록 userId 필터로 이동 가능하다.

## 18.5 오류 상태

- [ ] 검색 결과가 없을 때 빈 상태가 표시된다.
- [ ] 목록 조회 실패 시 다시 시도 버튼이 표시된다.
- [ ] CSV 다운로드 실패 시 오류 안내가 표시된다.

## 19. 개발 메모

```txt
사용자 이메일은 DB에 있더라도 관리자 API 응답에 포함하지 않는다.
목록 화면은 운영 조회 중심이며 위험 액션은 제공하지 않는다.
정지/해제는 반드시 A18 유저 상세에서 수행한다.
획득 수와 문의 수는 조인 또는 aggregate view로 내려주는 것을 권장한다.
대량 목록 성능을 위해 서버 페이지네이션을 기본으로 한다.
```
