# 1. 화면 개요

상품 수정 화면은 이미 등록된 상품의 기본 정보, 이미지, 외부 연동 상품 ID, 상태값을 수정하는 관리자 화면이다.

상품은 보물상자와 직접 1:1로 붙는 데이터가 아니라, `보물-상품 매칭` 화면을 통해 보물상자에 연결된다. 따라서 이 화면에서는 상품 자체의 정보만 수정하고, 특정 보물과의 연결 생성·교체·해제는 수행하지 않는다.

```txt
상품 상세
→ 상품 수정 클릭
→ 상품 정보 수정
→ 저장
→ 상품 상세로 복귀
```

---

# 2. 화면 목적

## 2.1 핵심 목적

- 등록된 상품 정보를 수정한다.
- 상품 이미지와 외부 연동 상품 ID를 수정한다.
- 상품의 운영 상태를 `active` 또는 `inactive`로 변경한다.
- active 상품을 inactive로 변경할 때 연결된 active 보물이 있으면 영향도를 안내한다.
- 저장 전 입력값을 검증한다.

## 2.2 이 화면에서 하지 않는 것

- 신규 상품 등록
- 상품 삭제
- 보물상자 생성·수정
- 보물-상품 매칭 생성·교체·해제
- 기프티쇼비즈 API 직접 호출
- 쿠폰 번호 조회
- 바코드 조회
- 사용자 이메일 조회
- 상품 API 자동 동기화

## 5.2 기본 정보 카드

### 입력 필드

| 필드 | key | 필수 | 타입 | 검증 |
|---|---|---:|---|---|
| 브랜드명 | `brand_name` | O | text | 1~50자 |
| 상품명 | `product_name` | O | text | 1~100자 |
| 상품 설명 | `description` | 선택 | textarea | 0~500자 |
| 판매 가격 | `price_krw` | O | number | 0 이상의 정수 |

### 표시 기준

- 모든 입력값은 기존 상품 데이터를 초기값으로 채운다.
- 가격은 입력 시 숫자만 허용한다.
- 화면 표시 시에는 `4,500원`처럼 천 단위 구분을 사용할 수 있다.
- 저장 요청 시에는 숫자 원문으로 전송한다.

## 5.3 상품 이미지 카드

### 구성

```txt
상품 이미지
[이미지 미리보기 영역]
[이미지 교체]
권장 크기: 800x800px, 최대 5MB
```

### 이미지 정책

| 항목 | 기준 |
|---|---|
| 허용 확장자 | JPG, PNG, WebP |
| 최대 용량 | 5MB |
| 권장 크기 | 800x800px |
| 저장 위치 | Supabase Storage |
| 미리보기 | 업로드 즉시 로컬 preview 표시 |

### 동작

| 액션 | 처리 |
|---|---|
| 이미지 교체 클릭 | 파일 선택 창 오픈 |
| 파일 선택 성공 | 미리보기 갱신 |
| 파일 검증 실패 | 필드 하단 오류 표시 |
| 저장 클릭 | 이미지가 변경된 경우 Storage 업로드 후 상품 정보 저장 |

### 주의

이미지 교체는 상품 이미지 URL만 변경한다. 기존에 연결된 보상, 보물상자 매칭, 발급 이력에는 영향을 주지 않는다.

## 5.4 외부 연동 및 상태 카드

### 입력 필드

| 필드 | key | 필수 | 타입 | 설명 |
|---|---|---:|---|---|
| 기프티쇼비즈 상품 ID | `provider_product_id` | O | text | 외부 발급 시스템 상품 식별자 |
| 상태 | `status` | O | select | `active`, `inactive` |

### 상태 옵션

| 상태 | 설명 |
|---|---|
| active | 보물 매칭에 사용할 수 있는 상품 |
| inactive | 신규 매칭에 사용할 수 없는 상품 |

### 상태 안내 문구

```txt
상태를 active로 전환하려면 외부 상품 ID가 필요합니다.
연결된 active 보물이 있을 경우 inactive 전환 시 영향 경고가 표시됩니다.
```

# 6. 상태 변경 정책

## 6.1 active 전환 가능 조건

상품 상태를 `active`로 저장하려면 아래 조건을 만족해야 한다.

```txt
상품명 존재
브랜드명 존재
판매 가격 존재
provider_product_id 존재
이미지 존재 권장
```

이미지는 MVP에서 필수로 둘 수도 있고 권장으로 둘 수도 있다. 현재 와이어프레임 기준으로는 이미지 영역이 있으므로, 개발에서는 `필수`보다는 `권장`으로 두는 것을 추천한다.

## 6.2 inactive 전환 경고

상품을 `active`에서 `inactive`로 변경하려는 경우, 해당 상품이 현재 active 보물에 연결되어 있는지 확인한다.

### 조건

```txt
기존 상태 = active
변경 상태 = inactive
active 상태 보물과 연결된 매칭 존재
```

### 경고 팝업

```txt
inactive 전환 경고
현재 이 상품에 연결된 active 보물이 있습니다.
상품을 inactive로 변경하면 해당 상품은 신규 매칭에 사용할 수 없습니다.
기존 연결 상태는 매칭 정책에 따라 별도 확인이 필요합니다.

[닫기] [수정 화면으로 이동]
```

### 버튼 동작

| 버튼 | 동작 |
|---|---|
| 닫기 | 팝업 닫기, 수정 화면 유지 |
| 수정 화면으로 이동 | 현재 화면 유지 또는 매칭 관리 화면 이동 정책 중 선택 |

권장 정책:

```txt
팝업의 2차 버튼명은 `매칭 관리로 이동`이 더 명확하다.
```

연결된 active 보물이 있다면 사용자가 상품 상태를 바꾸기 전에 매칭 관리 화면에서 영향 범위를 확인할 수 있어야 한다.


- [ ] viewer는 직접 URL 접근 시 접근 거부 화면으로 이동한다.

## 16.2 초기값

- [ ] 기존 상품 정보가 입력 필드에 정상 표시된다.
- [ ] 기존 이미지가 미리보기 영역에 표시된다.
- [ ] 기존 상태가 select에 반영된다.

## 16.3 입력 검증

- [ ] 브랜드명 필수 검증이 동작한다.
- [ ] 상품명 필수 검증이 동작한다.
- [ ] 판매 가격 숫자 검증이 동작한다.
- [ ] 외부 상품 ID 필수 검증이 동작한다.
- [ ] 이미지 형식/용량 검증이 동작한다.

## 16.4 상태 변경

- [ ] active 전환 조건이 검증된다.
- [ ] active 상품을 inactive로 변경할 때 연결된 active 보물이 있으면 경고가 표시된다.
- [ ] 경고 팝업에서 닫기 동작이 정상 동작한다.

## 16.5 저장

- [ ] 저장 성공 시 상품 상세 화면으로 이동한다.
- [ ] 저장 실패 시 입력값이 유지된다.
- [ ] 저장 실패 팝업이 표시된다.
- [ ] 저장 중 버튼이 disabled 처리된다.

## 16.6 보안

- [ ] 쿠폰 번호가 노출되지 않는다.
- [ ] 바코드가 노출되지 않는다.
- [ ] 사용자 이메일이 노출되지 않는다.
- [ ] 기프티쇼비즈 Secret이 노출되지 않는다.

# 17. 개발 메모

상품 등록 화면과 거의 동일한 폼 구조를 재사용하되, 수정 화면은 아래 차이가 있다.

```txt
등록 화면: 빈 값으로 시작
수정 화면: 기존 데이터로 초기화
등록 화면: 저장 성공 후 상품 상세 이동
수정 화면: 저장 성공 후 동일 상품 상세 이동
수정 화면: active → inactive 변경 시 연결 보물 영향 경고 필요
```
