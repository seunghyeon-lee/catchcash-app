## 2. 화면 개요

관리자 로그인 화면은 캐치캐쉬 관리자 CMS에 접근하기 전 관리자 인증을 수행하는 진입 화면이다.

관리자 CMS는 사용자 앱과 달리 Google, Kakao, Apple 소셜 로그인을 사용하지 않는다.  
관리자는 super_admin이 직접 생성한 이메일과 초기 비밀번호로 로그인한다.

이 화면은 다음 역할을 수행한다.

```txt
관리자 이메일 입력
→ 관리자 비밀번호 입력
→ Supabase Auth 로그인 요청
→ 관리자 계정 상태 확인
→ 관리자 역할 확인
→ 정상 계정이면 대시보드 이동
```

---

## 3. 화면 목적

### 3.1 핵심 목적

- 관리자 CMS 접근 전 인증을 수행한다.
- 이메일과 비밀번호 기반 로그인을 제공한다.
- 사용자 앱의 소셜 로그인과 관리자 로그인을 분리한다.
- 로그인 성공 후 관리자 계정 상태와 역할을 검증한다.
- 실패 사유에 따라 명확한 안내 메시지를 표시한다.

### 3.2 관리자 관점 목적

- 부여받은 관리자 계정으로 CMS에 로그인한다.
- 로그인 실패 사유를 확인한다.
- 비활성 또는 잠금 계정인 경우 관리자에게 문의해야 함을 인지한다.

## 4. 정책 기준

## 4.1 관리자 계정 정책

```txt
관리자 계정은 super_admin이 직접 생성한다.
관리자 계정 초대 메일과 초대 링크는 사용하지 않는다.
관리자 계정 셀프 비밀번호 찾기는 MVP 범위에서 제외한다.
관리자 CMS 역할은 super_admin, operator, viewer 3개다.
```

## 4.2 로그인 방식 정책

| 구분 | 정책 |
|---|---|
| 관리자 로그인 | 이메일 + 비밀번호 |
| 사용자 앱 로그인 | Google / Kakao / Apple 소셜 로그인 |
| 관리자 소셜 로그인 | 사용하지 않음 |
| 회원가입 버튼 | 노출하지 않음 |
| 초대 링크 | 노출하지 않음 |
| 비밀번호 찾기 | MVP에서는 노출하지 않음 |
| 2단계 인증 | MVP에서는 제공하지 않음 |

## 5. 진입 조건

## 5.1 진입 시점

사용자는 아래 상황에서 관리자 로그인 화면에 진입한다.

| 상황 | 설명 |
|---|---|
| `/admin` 최초 접근 | 관리자 세션이 없는 경우 |
| `/admin/login` 직접 접근 | 로그인 화면 직접 접근 |
| 세션 만료 | 기존 관리자 세션이 만료된 경우 |
| 로그아웃 완료 | 관리자 로그아웃 후 |
| inactive 계정 감지 | 세션 무효화 후 로그인 화면 복귀 |
| 인증 오류 | 세션 검증 실패 |

## 5.2 Route

```txt
/admin/login
```

Next.js App Router 기준 권장 파일 경로:

```txt
app/admin/login/page.tsx
```

## 5.3 로그인 상태 접근 처리

| 조건 | 처리 |
|---|---|
| 관리자 세션 없음 | 로그인 화면 표시 |
| 관리자 세션 있음 + active + role 정상 | `/admin` 또는 `/admin/dashboard` 이동 |
| 관리자 세션 있음 + inactive | 세션 무효화 후 로그인 화면 표시 |
| 관리자 세션 있음 + role 없음 | `/admin/access-denied` 이동 |
| 관리자 세션 있음 + role 불일치 | `/admin/access-denied` 이동 |

## 6. 종료 및 이동 규칙

| 조건 | 이동/처리 |
|---|---|
| 로그인 성공 + active + role 정상 | 대시보드 이동 |
| 로그인 성공 + role 없음 | 접근 권한 부족 화면 이동 |
| 로그인 성공 + role 불일치 | 접근 권한 부족 화면 이동 |
| 로그인 성공 + inactive | 세션 무효화 + 로그인 화면 유지 |
| 이메일/비밀번호 불일치 | 로그인 화면 유지 + 실패 메시지 표시 |
| 계정 잠금 | 로그인 화면 유지 + 잠금 메시지 표시 |
| 서버 오류 | 로그인 화면 유지 + 오류 메시지 표시 |

권장 이동 Route:

```txt
정상 로그인: /admin 또는 /admin/dashboard
접근 제한: /admin/access-denied
```

## 7.2 레이아웃 원칙

- 관리자 CMS는 모바일 앱의 rough UI가 아니라 SaaS형 관리자 UI로 구성한다.
- 화면 중앙에 로그인 폼을 배치한다.
- 폼 영역은 과도하게 넓히지 않고 320px~420px 수준을 권장한다.
- 배경은 밝은 회색 또는 흰색 기반으로 한다.
- 관리자 로그인에서는 사용자 앱 하단 탭바, GNB, 캐릭터 UI를 사용하지 않는다.
- 로그인 실패 메시지는 폼 아래에 1개만 표시한다.

## 9. 상태 정의

## 9.1 클라이언트 상태 타입

```ts
type AdminLoginStatus =
  | 'idle'
  | 'submitting'
  | 'success'
  | 'invalid_credentials'
  | 'inactive'
  | 'locked'
  | 'role_missing'
  | 'role_mismatch'
  | 'server_error';
```

## 9.2 상태별 UI 처리

| 상태 | 화면 처리 |
|---|---|
| `idle` | 기본 로그인 폼 표시 |
| `submitting` | 로그인 버튼 disabled, 로딩 텍스트 표시 |
| `success` | 대시보드 이동 |
| `invalid_credentials` | 로그인 실패 메시지 카드 표시 |
| `inactive` | 계정 비활성 메시지 카드 표시 |
| `locked` | 계정 잠금 메시지 카드 표시 |
| `role_missing` | `/admin/access-denied` 이동 |
| `role_mismatch` | `/admin/access-denied` 이동 |
| `server_error` | 서버 오류 메시지 카드 표시 |

## 9.3 오류 메시지 노출 원칙

```txt
로그인 오류 메시지는 한 번에 하나만 표시한다.
여러 오류가 동시에 발생한 것처럼 보이게 하지 않는다.
```

오류 우선순위:

```txt
locked
→ inactive
→ role_missing / role_mismatch
→ invalid_credentials
→ server_error
```

## 11. 로그인 처리 플로우

## 11.1 기본 플로우

```txt
1. 사용자가 이메일과 비밀번호를 입력한다.
2. 로그인 버튼을 클릭한다.
3. 클라이언트에서 필수값과 이메일 형식을 검증한다.
4. 검증 실패 시 필드 오류를 표시한다.
5. 검증 성공 시 Supabase Auth 로그인 요청을 보낸다.
6. 인증 실패 시 로그인 실패 메시지를 표시한다.
7. 인증 성공 시 관리자 프로필을 조회한다.
8. 관리자 계정 상태가 active인지 확인한다.
9. 관리자 role이 super_admin/operator/viewer 중 하나인지 확인한다.
10. 모든 조건 통과 시 대시보드로 이동한다.
```

## 12. 권한 및 보안 기준

## 12.1 클라이언트 보안

```txt
SUPABASE_SERVICE_ROLE_KEY는 브라우저에 노출하지 않는다.
관리자 계정 생성 API는 로그인 화면에서 호출하지 않는다.
기프티쇼비즈 관련 secret은 로그인 화면에서 사용하지 않는다.
```

## 12.2 서버 검증

```txt
로그인 성공 후에도 서버에서 관리자 role과 status를 재검증한다.
UI에서 버튼을 숨기는 것과 별개로 보호 Route에서도 권한을 검증한다.
관리자 role이 없거나 불일치하면 접근 제한 화면으로 이동한다.
```

## 12.3 로깅 정책

| 이벤트 | 로그 필요 여부 | 설명 |
|---|---:|---|
| 로그인 성공 | 필요 | 일반 운영 또는 보안 로그 정책에 따라 기록 |
| 로그인 실패 | 필요 | 반복 실패 감지용 |
| inactive 로그인 시도 | 필요 | 보안 확인용 |
| 계정 잠금 | 필요 | 보안 로그 대상 |
| role 없음 접근 | 필요 | 권한 불일치 확인용 |

| 용도 | 값 |
|---|---|
| 페이지 배경 | `#F8FAFC` 또는 `#FFFFFF` |
| 카드 배경 | `#FFFFFF` |
| 기본 텍스트 | `#111827` |
| 보조 텍스트 | `#6B7280` |
| 입력선 | `#D1D5DB` |
| 주요 버튼 | `#111827` |
| 주요 버튼 텍스트 | `#FFFFFF` |
| 오류 배경 | `#F9FAFB` |
| 오류 테두리 | `#E5E7EB` |

## 15.2 간격

| 요소 | 권장값 |
|---|---:|
| 로그인 폼 최대 너비 | 360px~420px |
| 필드 간격 | 12px~16px |
| 버튼 상단 여백 | 16px |
| 오류 카드 간격 | 12px |
| 화면 상단 여백 | 48px~80px |

## 15.3 관리자 UI 톤

```txt
사용자 앱의 손그림 rough UI를 그대로 적용하지 않는다.
관리자 CMS는 명확하고 안정적인 SaaS 운영툴 톤을 사용한다.
캐치캐쉬 브랜드명은 유지하되, 문구는 관리자용으로 차분하게 작성한다.
```

|---|---|

## 18. QA 체크리스트

## 18.1 기본 동작

| 체크 항목 | 기대 결과 |
|---|---|
| 이메일 미입력 후 로그인 | 이메일 필드 오류 표시 |
| 비밀번호 미입력 후 로그인 | 비밀번호 필드 오류 표시 |
| 잘못된 이메일 형식 | 이메일 형식 오류 표시 |
| 잘못된 계정 정보 | 로그인 실패 카드 1개 표시 |
| 정상 계정 로그인 | 대시보드 이동 |

## 18.2 상태별 검증

| 체크 항목 | 기대 결과 |
|---|---|
| inactive 계정 로그인 | 계정 비활성 안내 표시 |
| 잠금 계정 로그인 | 계정 잠금 안내 표시 |
| role 없는 계정 로그인 | 접근 권한 부족 화면 이동 |
| role 불일치 계정 로그인 | 접근 권한 부족 화면 이동 |
| 서버 오류 발생 | 서버 오류 카드 표시 |

## 18.3 보안 검증

| 체크 항목 | 기대 결과 |
|---|---|
| 브라우저에서 service role key 확인 | 노출되지 않음 |
| 로그인 전 `/admin` 접근 | 로그인 화면 이동 |
| 로그인 후 권한 없는 route 직접 접근 | A24 접근 권한 부족 화면 표시 |
| 로그아웃 후 뒤로가기 | 보호 화면 재진입 불가 |
