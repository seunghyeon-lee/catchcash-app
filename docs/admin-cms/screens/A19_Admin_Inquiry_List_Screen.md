## 2. 화면 개요

문의 목록 화면은 사용자 앱에서 등록된 문의글을 관리자 CMS에서 조회하는 화면이다.

관리자는 문의 ID, 유저 ID, 유저 닉네임, 문의 내용, 카테고리, 상태, 답변 여부, 연관 보상, 접수일 기준으로 문의를 검색하고 필터링할 수 있다.

이 화면은 문의 답변을 직접 작성하는 화면이 아니다.  
답변 작성, 상태 변경, 내부 메모 작성은 `A20_Admin_Inquiry_Detail_Screen`에서 처리한다.

중요:

```txt
문의 목록은 문의 조회와 상세 진입을 위한 화면이다.
답변 작성은 문의 상세 화면에서만 수행한다.
viewer는 문의 목록과 상세 조회만 가능하다.
viewer는 답변 작성, 상태 변경, 내부 메모 작성이 불가능하다.
사용자 이메일은 표시하지 않는다.
쿠폰 번호와 바코드는 표시하지 않는다.
```

---

## 3. 화면 목적

### 3.1 관리자 목적

- 접수된 문의 목록을 확인한다.
- 미처리 문의를 빠르게 찾는다.
- 카테고리와 상태별로 문의를 분류한다.
- 연관 보상 문의를 확인한다.
- 특정 문의 상세 화면으로 이동한다.
- CSV로 문의 목록을 내보낸다.

### 3.2 시스템 목적

- 사용자 문의와 관리자 답변 상태를 일관되게 관리한다.
- 문의 상태와 답변 여부를 분리해서 보여준다.
- 사용자 앱 문의 답변 확인 화면과 연결될 데이터를 관리한다.
- 개인정보와 쿠폰 민감 정보 노출 없이 운영에 필요한 정보만 제공한다.

## 6. 화면 구조

와이어프레임 기준 화면 구성은 아래 순서로 확정한다.

```txt
AdminLayout
→ 상단 헤더
→ 화면 타이틀
→ 우측 CSV 내보내기 버튼
→ 검색 및 필터 영역
→ 조회 오류 배너
→ 문의 목록 테이블
→ 페이지네이션
→ 문의 상세 이동 확인 팝업
```

## 8.2 카테고리 필터

사용자 앱 문의 카테고리와 관리자 CMS 카테고리를 동일한 Enum으로 관리한다.

| 라벨 | 값 |
|---|---|
| 전체 | `all` |
| 이용 문의 | `usage` |
| 쿠폰 문의 | `coupon` |
| 보상 문의 | `reward` |
| 계정 문의 | `account` |
| 오류 제보 | `error` |
| 개선 문의 | `improvement` |
| 기타 문의 | `other` |

---

## 8.3 상태 필터

| 라벨 | 값 | 설명 |
|---|---|---|
| 전체 | `all` | 전체 문의 |
| 접수 | `open` | 새로 접수된 문의 |
| 처리 중 | `in_progress` | 운영자가 확인 중인 문의 |
| 답변 완료 | `answered` | 사용자에게 답변 완료 |
| 종료 | `closed` | 처리 종료 |

---

## 8.4 답변 여부 필터

| 라벨 | 값 |
|---|---|
| 전체 | `all` |
| 답변 전 | `unanswered` |
| 답변 완료 | `answered` |

답변 여부는 `answer_body` 또는 `answered_at` 기준으로 판단한다.

---

## 8.5 연관 보상 필터

| 라벨 | 값 | 설명 |
|---|---|---|
| 전체 | `all` | 전체 문의 |
| 연관 보상 있음 | `has_reward` | reward_id가 있는 문의 |
| 연관 보상 없음 | `no_reward` | reward_id가 없는 문의 |

쿠폰·보상 문의의 경우 연관 보상이 있을 수 있다.

---

## 8.6 기간 필터

기준은 문의 접수일 `created_at`으로 한다.

| 필터 | 설명 |
|---|---|
| 시작일 | 조회 시작일 |
| 종료일 | 조회 종료일 |

---

## 8.7 정렬 옵션

| 라벨 | 값 |
|---|---|
| 최근 접수순 | `created_desc` |
| 오래된 접수순 | `created_asc` |

## 9.2 상태 배지

| 상태 | 의미 | UI |
|---|---|---|
| open | 신규 접수 | 기본 강조 배지 |
| in_progress | 처리 중 | 진행 배지 |
| answered | 답변 완료 | 완료 배지 |
| closed | 종료 | 비활성 배지 |

---

## 9.3 답변 여부 표시

| 값 | 의미 |
|---|---|
| 답변 전 | `answered_at` 없음 |
| 답변 완료 | `answered_at` 있음 |

상태가 `answered`가 아니더라도 임시 저장 답변을 지원하지 않는 MVP에서는 답변 완료 여부는 `answered_at` 기준으로 단순화한다.

## 15.4 접근 권한 없음

문의 목록은 viewer까지 접근 가능하므로 일반적으로 접근 권한 없음 상태가 발생하지 않는다.  
권한 정보가 없거나 서버 검증에서 실패하면 A24 접근 권한 부족 화면으로 이동한다.

## 16. 사용자 앱 연계

사용자 앱 문의 등록 화면에서 저장된 문의는 이 목록에 노출된다.

사용자 앱 문의 카테고리는 관리자 CMS와 동일한 Enum을 사용한다.

답변이 저장되면 사용자 앱에는 알림이 생성되어야 한다.

```txt
notification.type = notice
notification.subtype = inquiry_answer
deep_link = /support/inquiries/{inquiryId}
```

따라서 사용자 앱에는 아래 화면이 필요하다.

```txt
/support/inquiries
/support/inquiries/[inquiryId]
```

## 17. 보안 정책

```txt
사용자 이메일은 관리자 CMS에서 수집·조회·표시하지 않는다.
쿠폰 번호와 바코드는 목록과 CSV에 포함하지 않는다.
문의 내용에 개인정보가 포함될 수 있으므로 불필요한 전체 본문 노출을 피한다.
목록에서는 제목 요약 또는 일부 미리보기만 표시한다.
답변 작성과 상태 변경은 A20 상세 화면에서만 수행한다.
CSV 내보내기는 서버에서 권한을 재검증한다.
```

## 20. QA 체크리스트

## 20.1 권한

- [ ] super_admin은 문의 목록을 조회할 수 있다.
- [ ] operator는 문의 목록을 조회할 수 있다.
- [ ] viewer는 문의 목록을 조회할 수 있다.
- [ ] viewer에게 CSV 내보내기 버튼은 보이지 않는다.
- [ ] 답변 작성 버튼은 목록 화면에 표시되지 않는다.

## 20.2 검색·필터

- [ ] 유저 ID로 검색할 수 있다.
- [ ] 닉네임으로 검색할 수 있다.
- [ ] 문의 내용으로 검색할 수 있다.
- [ ] 카테고리 필터가 정상 동작한다.
- [ ] 상태 필터가 정상 동작한다.
- [ ] 답변 여부 필터가 정상 동작한다.
- [ ] 연관 보상 필터가 정상 동작한다.
- [ ] 시작일/종료일 필터가 정상 동작한다.
- [ ] 정렬 옵션이 정상 동작한다.

## 20.3 테이블

- [ ] 문의 ID가 표시된다.
- [ ] 카테고리가 표시된다.
- [ ] 제목 요약이 표시된다.
- [ ] 유저 닉네임이 표시된다.
- [ ] 상태가 표시된다.
- [ ] 답변 여부가 표시된다.
- [ ] 연관 보상이 표시된다.
- [ ] 접수일시가 표시된다.

- [ ] 쿠폰 번호와 바코드는 표시되지 않는다.

## 20.4 이동

- [ ] 문의 행 클릭 시 상세 이동 팝업이 열린다.
- [ ] 취소 클릭 시 팝업이 닫힌다.
- [ ] 상세 보기 클릭 시 A20 문의 상세로 이동한다.
- [ ] 유저 닉네임 클릭 시 A18 유저 상세로 이동한다.
- [ ] 연관 보상 클릭 시 A16 보상 상세로 이동한다.

## 20.5 오류 상태

- [ ] 목록 조회 실패 시 오류 배너가 표시된다.
- [ ] 다시 시도 클릭 시 목록 API를 재호출한다.
- [ ] 검색 결과가 없을 때 빈 상태가 표시된다.
- [ ] CSV 다운로드 실패 시 오류 안내가 표시된다.

## 21. 개발 메모

```txt
A19는 문의 처리의 진입 화면이다.
답변 작성, 상태 변경, 내부 메모는 A20 상세 화면에서만 제공한다.
사용자 문의 카테고리는 사용자 앱과 관리자 CMS가 같은 Enum을 사용해야 한다.

목록에서는 긴 문의 본문 전체를 노출하지 않고 제목 또는 요약만 표시한다.
```
