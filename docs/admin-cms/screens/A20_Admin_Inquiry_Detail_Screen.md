## 2. 화면 개요

문의 상세 화면은 사용자 앱에서 등록된 문의 1건을 관리자 CMS에서 확인하고 처리하는 화면이다.

관리자는 문의 기본 정보, 문의 본문, 연관 유저, 연관 보상, 답변 내용, 내부 메모, 운영 로그 요약을 확인할 수 있다.

super_admin과 operator는 답변 작성, 상태 변경, 내부 메모 저장이 가능하다.  
viewer는 조회만 가능하며 답변 작성, 상태 변경, 내부 메모 저장은 할 수 없다.

중요:

```txt
문의 상세는 문의 처리의 실제 작업 화면이다.
문의 목록 A19에서는 답변 작성과 상태 변경을 하지 않는다.
사용자 이메일은 표시하지 않는다.
쿠폰 번호와 바코드는 표시하지 않는다.
답변 저장 시 사용자 앱 알림을 생성한다.
내부 메모는 사용자에게 노출하지 않는다.
```

---

## 3. 화면 목적

### 3.1 관리자 목적

- 문의 상세 내용을 확인한다.
- 문의와 연관된 유저 및 보상 정보를 확인한다.
- 사용자에게 전달할 답변을 작성한다.
- 문의 상태를 변경한다.
- 내부 운영 메모를 기록한다.
- 처리 이력과 운영 로그를 확인한다.

### 3.2 시스템 목적

- 문의 처리 상태를 명확하게 관리한다.
- 관리자 답변을 사용자 앱에서 확인할 수 있도록 저장한다.
- 답변 저장 시 사용자 알림을 생성한다.
- 내부 메모와 사용자 답변을 분리한다.
- 문의 처리 관련 관리자 작업을 운영 로그로 남긴다.

## 5. 접근 권한

### 5.1 접근 가능 조건

```txt
관리자 세션 존재
admin.status = active
admin.role in ('super_admin', 'operator', 'viewer')
```

### 5.2 권한 매트릭스

| 기능 | super_admin | operator | viewer |
|---|---:|---:|---:|
| 문의 상세 조회 | O | O | O |
| 문의 본문 조회 | O | O | O |
| 연관 유저 이동 | O | O | O |
| 연관 보상 이동 | O | O | O |
| 답변 작성 | O | O | X |
| 답변 저장 | O | O | X |
| 상태 변경 | O | O | X |
| 내부 메모 조회 | O | O | O |
| 내부 메모 저장 | O | O | X |
| 운영 로그 요약 조회 | O | O | X 권장 |
| 사용자 이메일 조회 | X | X | X |
| 쿠폰 번호·바코드 조회 | X | X | X |

viewer는 조회 전용 역할이다.  
viewer에게 답변 textarea, 상태 변경 select, 내부 메모 저장 버튼은 disabled 또는 미노출 처리한다.

## 11. 답변 작성 영역

## 11.1 목적

사용자에게 전달할 답변 내용을 작성하고 저장하는 영역이다.

중요:

```txt
답변 내용은 사용자 앱 문의 상세 화면에 노출된다.
답변 저장 시 사용자 알림을 생성한다.
내부 메모와 혼동되지 않도록 라벨을 명확히 표시한다.
```

---

## 11.2 UI 구성

```txt
답변 작성
→ 답변 내용 textarea
→ 답변 저장 버튼
```

### 필드 정의

| 항목 | 기준 |
|---|---|
| 라벨 | `답변 내용` |
| placeholder | `사용자에게 전달할 답변을 입력하세요.` |
| 최소 글자 수 | 2자 이상 권장 |
| 최대 글자 수 | 2,000자 이하 권장 |
| 저장 버튼 | `답변 저장` |

---

## 11.3 답변 저장 조건

| 조건 | 처리 |
|---|---|
| 답변 내용 비어 있음 | 저장 불가 |
| viewer | 저장 불가 |
| 문의 상태 closed | 저장 가능 여부 정책 필요, 기본은 가능하되 재오픈 경고 권장 |
| 저장 중 | 버튼 disabled + loading |
| 저장 성공 | 답변 저장 + 알림 생성 + 상태 answered 권장 |
| 저장 실패 | 오류 안내 + 입력값 유지 |

---

## 11.4 답변 저장 후 처리

답변 저장 성공 시 다음 데이터를 저장한다.

```txt
answer_body
answered_at
answered_by_admin_id
status = answered 권장
updated_at
```

사용자 앱 알림 생성:

```txt
notification.type = notice
notification.subtype = inquiry_answer
deep_link = /support/inquiries/{inquiryId}
```

## 12. 내부 메모 영역

## 12.1 목적

관리자 내부에서만 확인하는 운영 메모를 작성하는 영역이다.

중요:

```txt
내부 메모는 사용자 앱에 절대 노출하지 않는다.
viewer에게는 메모 조회만 허용하고 저장은 불가하다.
```

---

## 12.2 UI 구성

```txt
내부 메모
→ 안내 문구
→ 메모 입력 textarea
→ 메모 저장 버튼
```

### 안내 문구

```txt
viewer에게는 표시되지 않는 내부 운영 메모입니다.
```

※ 실제 정책상 viewer에게 내부 메모를 보여줄지 여부는 프로젝트 정책에 따라 결정한다.  
MVP 권장안은 viewer에게 메모 조회는 가능하되 작성은 불가로 한다. 민감한 메모가 많아질 경우 P1에서 viewer 조회도 차단한다.

---

## 12.3 메모 저장 조건

| 조건 | 처리 |
|---|---|
| super_admin/operator | 저장 가능 |
| viewer | 저장 불가 |
| 변경 내용 없음 | 저장 버튼 disabled |
| 저장 성공 | 성공 토스트 |
| 저장 실패 | 오류 안내 |

| 역할 | 노출 |

## 24. QA 체크리스트

## 24.1 권한

- [ ] super_admin은 문의 상세를 조회할 수 있다.
- [ ] operator는 문의 상세를 조회할 수 있다.
- [ ] viewer는 문의 상세를 조회할 수 있다.
- [ ] super_admin은 답변을 저장할 수 있다.
- [ ] operator는 답변을 저장할 수 있다.
- [ ] viewer는 답변을 저장할 수 없다.
- [ ] viewer는 상태 변경을 할 수 없다.
- [ ] viewer는 내부 메모를 저장할 수 없다.

## 24.2 기본 정보

- [ ] 문의 제목이 표시된다.
- [ ] 카테고리가 표시된다.
- [ ] 상태가 표시된다.
- [ ] 답변 여부가 표시된다.
- [ ] 작성자가 유저 ID/닉네임 기준으로 표시된다.
- [ ] 작성 시각이 표시된다.
- [ ] 최근 수정 시각이 표시된다.
- [ ] 사용자 이메일은 표시되지 않는다.

## 24.3 답변

- [ ] 답변 내용 입력이 가능하다.
- [ ] 답변이 비어 있으면 저장할 수 없다.
- [ ] 답변 저장 성공 시 answered_at이 저장된다.
- [ ] 답변 저장 성공 시 사용자 알림이 생성된다.
- [ ] 답변 저장 실패 시 입력값이 유지된다.

## 24.4 상태 변경

- [ ] 상태 선택이 가능하다.
- [ ] 현재 상태와 같은 값을 선택하면 적용 버튼이 비활성화된다.
- [ ] 상태 적용 클릭 시 확인 팝업이 열린다.
- [ ] 변경 사유 미입력 시 적용할 수 없다.
- [ ] 상태 변경 성공 시 화면 상태가 갱신된다.
- [ ] 상태 변경은 운영 로그로 기록된다.

## 24.5 내부 메모

- [ ] 내부 메모를 저장할 수 있다.
- [ ] viewer는 메모 저장을 할 수 없다.
- [ ] 내부 메모는 사용자 앱에 노출되지 않는다.

## 24.6 이동

- [ ] 유저 상세로 이동할 수 있다.
- [ ] 문의 목록으로 이동할 수 있다.
- [ ] 연관 보상 상세로 이동할 수 있다.
- [ ] 연관 보물 상세로 이동할 수 있다.
