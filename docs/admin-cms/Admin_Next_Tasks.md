# CatchCash Admin CMS Next Tasks

작성일: 2026-08-02  
단계: 문의 관리 CMS 1차 완료 후 관리자 기능 확장 준비

---

## 1. 목적

이 문서는 캐치캐쉬 관리자 CMS에서 문의 관리 이후 다음에 개발할 기능과 우선순위를 정리하기 위한 문서다.

현재 관리자 CMS는 문의 관리 기능을 중심으로 1차 구현되어 있다.  
다음 단계에서는 보상/쿠폰, 보물상자, 유저 관리, 운영 로그, 관리자 권한 기능을 순서대로 확장한다.

---

## 2. 현재 완료된 관리자 CMS

현재 완료된 관리자 CMS 범위는 아래와 같다.

- `/admin/login`
- `/admin/dashboard`
- `/admin/inquiries`
- `/admin/inquiries/[id]`

완료된 주요 기능:

- 관리자 로그인 화면 shell
- 관리자 대시보드 shell
- 문의 목록 화면
- 문의 상세 화면
- 문의 답변 등록 구조
- 답변 등록 후 사용자 알림 생성 구조
- 사용자 문의/관리자 답변 흐름 1차 연결

## 3. 다음 작업 우선순위

관리자 CMS의 다음 작업 우선순위는 아래 순서로 진행한다.

3. operation_logs 기록 기준 정리
4. 보상/쿠폰 상품 관리
5. 보물상자 관리
6. 유저 관리
7. 관리자 권한/Auth
8. 대시보드 통계 고도화

## 4. 1순위 — 문의 관리 QA

문의 관리 기능은 이미 1차 구현되어 있으므로, 다음 단계에서는 기능이 안정적으로 동작하는지 확인한다.

확인할 항목:

- 문의 목록이 정상 표시되는가
- 문의 상세가 정상 표시되는가
- 답변 등록이 정상 동작하는가
- 답변 등록 후 문의 상태가 `resolved`로 변경되는가
- 답변 등록 후 `support_replies`에 답변이 저장되는가
- 답변 등록 후 `notifications`가 생성되는가
- 사용자 앱에서 답변 도착 알림을 확인할 수 있는가
- 알림 클릭 시 `/support/[inquiryId]`로 이동하는가

---

## 5. 2순위 — operation_logs 기록 기준

관리자 CMS에서 중요한 작업은 추후 `operation_logs`에 기록한다.

기록 대상 예시:

- 관리자 로그인
- 문의 답변 등록
- 문의 상태 변경
- 보상 상품 등록
- 보상 상품 수정
- 보상 상품 비활성화
- 보물상자 등록
- 보물상자 수정
- 보물상자 비활성화
- 유저 상태 변경
- 관리자 권한 변경

1차 MVP에서는 모든 로그를 바로 연결하지 않고,  
중요한 관리자 액션부터 순차적으로 연결한다.

우선 연결 후보:

1. 문의 답변 등록
2. 보상 상품 등록/수정
3. 보물상자 등록/수정
4. 유저 상태 변경

---

## 6. 3순위 — 보상/쿠폰 상품 관리

관리자 CMS의 다음 주요 개발 대상은 보상/쿠폰 상품 관리다.

추천 라우트:

- `/admin/rewards`
- `/admin/rewards/new`
- `/admin/rewards/[id]`

관련 테이블:

- `gift_products`
- `treasure_rewards`
- `inventory_items`

1차 기능:

- 보상 상품 목록 조회
- 보상 상품 상세 조회
- 보상 상품 등록 shell
- 브랜드명 표시
- 상품명 표시
- 상품 타입 표시
- 재고 수량 표시
- 상태 표시
- 등록일 표시

1차에서는 Supabase 연결 없이 mock shell로 구현한다.  
이후 DB 연결 단계에서 `gift_products`를 기준으로 연결한다.

추천 라우트:

- `/admin/treasures`

- `/admin/treasures/[id]`

관련 테이블:

- `treasure_boxes`

1차 기능:

- 보물상자 목록 조회
- 보물상자 상세 조회

유저 관리는 관리자 CMS에서 후순위로 진행한다.

추천 라우트:

- `/admin/users/[id]`

관련 테이블:

- `profiles`
- `treasure_claims`
- `inventory_items`
- `support_inquiries`

1차 기능:

- 유저 목록 조회
- 유저 상세 조회
- 닉네임 확인
- 가입일 확인
- 보유 보상 수 확인
- 문의 이력 확인
- 사냥 참여 이력 확인

유저 정지/차단 기능은 MVP 이후 단계로 분리한다.

---

## 9. 6순위 — 관리자 권한/Auth

관리자 로그인/Auth는 별도 단계로 분리한다.

관련 테이블:

- `admin_users`
- `security_logs`
- `operation_logs`

관리자 Auth 기준:

- 일반 사용자 로그인과 분리
- 관리자 계정만 `/admin/**` 접근 가능
- 권한 없는 사용자는 관리자 화면 접근 불가
- 관리자 접근 실패는 `security_logs` 기록 후보

1차에서는 관리자 Auth를 바로 고도화하지 않고,  
기능 shell과 데이터 흐름 정리 후 진행한다.
