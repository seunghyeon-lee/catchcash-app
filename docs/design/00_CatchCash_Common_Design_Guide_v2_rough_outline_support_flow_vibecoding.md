## 2. 사용 방법

각 화면별 바이브코딩 지시문를 작성할 때 이 문서를 **공통 디자인 지시문**으로 먼저 붙인다.

권장 구조:

```txt
[공통 디자인 지시문]
+ [화면별 목적]
+ [화면별 UI 구성]
+ [화면별 기능/상태]
+ [화면별 에셋 분리 요청]
```

바이브코딩 작업을 요청할 때는 아래처럼 시작한다.

```txt
아래 공통 디자인 지시문을 반드시 지켜서
캐치캐쉬 {화면명} 화면 디자인을 만들어줘.

공통 디자인 지시문:
{00_CatchCash_Common_Design_Prompt_Guide.md 내용}

화면별 요구사항:
{해당 화면 MD 내용 요약}
```

## 3. 앱 개요

캐치캐쉬는 사용자가 지도에서 주변 보물을 찾고, AR 사냥을 통해 보상을 획득하는 위치 기반 리워드 앱이다.

핵심 흐름:

```txt
앱 실행
→ 로그인
→ 지도에서 주변 보물 확인
→ 힌트 확인
→ AR 사냥
→ 보상 획득
→ 보관함에서 쿠폰 확인
```

디자인은 보물찾기 앱의 재미를 담되, 지나치게 귀엽거나 컬러풀한 게임처럼 보이면 안 된다.  
서비스형 모바일 앱처럼 구조가 명확하고, 화면별 정보 위계가 분명해야 한다.

---

## 4. 전체 디자인 컨셉

캐치캐쉬 전체 앱 디자인은 레퍼런스 이미지처럼 **흑백 스케치 기반 모바일 UI 스타일**을 따른다.

디자인 키워드:

```txt
black and white
hand-drawn wireframe
sketch-style mobile UI
minimal
bold rough outline
slightly crooked linework
uneven sketch border
paper-like background
monochrome illustration
rough but readable
clean information hierarchy
mobile app prototype aesthetic
playful but not childish
sarcastic brand tone
```

전체적으로 완성형 상업 앱처럼 지나치게 매끈하고 화려한 UI가 아니라,  
**손으로 그린 듯한 흑백 앱 시안 / 스케치 프로토타입**처럼 보여야 한다.

단, 구조는 실제 개발 가능한 모바일 앱처럼 명확해야 한다.

가장 중요한 원칙은 아래와 같다.

```txt
구조는 정갈하게.
선은 거칠게.
```

삐뚤빼뚤함은 레이아웃이 무너지는 것이 아니라, 카드·버튼·입력창·탭의 외곽선 질감에서 표현되어야 한다.

## 5. 최종 디자인 목표

최종 결과는 아래 문장으로 요약된다.

```txt
흑백 손그림 스타일의 위치 기반 보물찾기 리워드 앱
```

모바일 앱 구조는 명확하게 유지한다.  
UI 요소는 굵고 거친 검은 선과 종이 질감 배경으로 정리한다.  
보물찾기 감성은 지도, 보물상자, 헌터, 쿠폰 스케치로 은은하게 표현한다.

최종 디자인은 아래 감성을 가져야 한다.

```txt
정렬된 모바일 앱 레이아웃 위에
손으로 직접 그린 듯한 삐뚤빼뚤한 외곽선을 입힌
흑백 스케치형 UI
```

## 6. 브랜드 말투 / 카피라이팅 톤

캐치캐쉬의 말투는 평범하게 친절한 앱 말투가 아니다.  
레퍼런스 이미지처럼 약간 **싸가지없고, 건방지고, 도발적인 말투**를 사용한다.

단, 사용자를 실제로 모욕하거나 혐오하거나 공격하면 안 된다.  
브랜드 캐릭터가 장난스럽게 툭툭 던지는 느낌이어야 한다.

### 6.1 말투 키워드

```txt
건방진
시니컬한
툭 던지는
짧고 강한
장난스러운
헌터 세계관이 있는
너무 친절하지 않은
하지만 불쾌하지 않은
```

### 6.2 말투 원칙

- 존댓말보다 반말 또는 짧은 명령형을 우선한다.
- 설명은 길게 하지 않는다.
- 버튼 문구는 짧고 강하게 쓴다.
- 안내 문구는 약간 도발적으로 쓴다.
- 사용자를 비하하거나 모욕하는 표현은 금지한다.
- 욕설, 혐오, 차별, 인신공격 표현은 금지한다.
- 법적/개인정보/약관 문구는 장난치지 말고 명확하게 쓴다.

### 6.3 좋은 카피 예시

| 일반적인 문구 | 캐치캐쉬 톤 |
|---|---|
| 시작하기 | 사냥 시작 |
| 회원가입하기 | 사냥 합류하기 |
| 로그인해주세요 | 들어와. 보물은 기다려주지 않아 |
| 닉네임을 입력해주세요 | 널 뭐라 부르냐? |
| 닉네임을 정해주세요 | 별명 하나는 있어야지 |
| 쿠폰을 확인해주세요 | 네 전리품이나 확인해 |
| 주변 보물을 찾아보세요 | 근처에 뭐 좀 숨겨놨다 |
| 보상이 없습니다 | 아직 빈손이네 |
| 다시 시도해주세요 | 다시 해봐 |
| 로그아웃하시겠습니까? | 진짜 나가게? |
| 문의 내용을 입력해주세요 | 뭔 일인지 말해봐 |
| 제출하기 | 던져놓기 |

### 6.4 사용 금지 카피

아래처럼 사용자를 직접 깎아내리는 표현은 금지한다.

```txt
멍청하네
한심하네
너 때문에 실패했어
니가 잘못했어
꺼져
바보
욕설
혐오 표현
성별/인종/지역/장애/나이 비하
```

### 6.5 화면별 말투 강도

| 화면 | 말투 강도 |
|---|---|
| 스플래시 | 약함 |
| 로그인 | 중간 |
| 닉네임/약관 | 중간~강함 |
| 홈 | 중간 |
| 지도/힌트 | 중간~강함 |
| AR 사냥 | 강함 |
| 성공/실패 결과 | 강함 |
| 보관함/쿠폰 | 중간 |
| 문의하기 | 중간 |
| 약관/개인정보 | 낮음, 정확성 우선 |

## 7. 색상 규칙

색상은 거의 사용하지 않고 흑백 중심으로 구성한다.

### 7.1 허용 색상

| 용도 | 색상 |
|---|---|
| 메인 텍스트 / 버튼 / 주요 라인 | `#000000` |
| 카드 / 버튼 내부 / 입력 필드 | `#FFFFFF` |
| 종이 같은 배경 | `#F7F5EF` |
| 연한 구분선 / 흐린 배경 | `#E8E5DC` |
| 보조 텍스트 | `#777777` |
| 비활성 / 흐린 선 | `#C9C9C9` |
| 위험/오류 강조 | `#000000` 또는 짙은 회색 기반으로 표현 |

### 7.2 색상 사용 원칙

- 전체 화면은 `#F7F5EF` 또는 아주 연한 베이지 배경을 기본으로 한다.
- 주요 텍스트와 주요 라인은 `#000000`을 사용한다.
- 카드 내부는 `#FFFFFF` 또는 종이 배경색을 사용한다.
- 비활성 상태는 `#C9C9C9` 또는 낮은 명도의 회색으로 처리한다.
- 상태 배지는 컬러가 아니라 선, 채움, 점선, 명도 차이로 구분한다.

### 7.3 금지 색상/표현

```txt
강한 원색
그라데이션
네온 컬러
강한 초록색/주황색 UI
화려한 컬러 팔레트
컬러풀한 게임 UI
```

## 8. 폰트 스타일

폰트는 손그림 느낌이 살짝 나는 굵은 산세리프 스타일로 표현한다.

### 8.1 기준 폰트

| 용도 | 기준 |
|---|---|
| Headline | Plus Jakarta Sans Bold 느낌 |
| Body | Plus Jakarta Sans Regular 느낌 |
| Label | Space Grotesk 느낌 |

### 8.2 텍스트 스타일 원칙

- 제목은 굵고 또렷하게 표현한다.
- 본문은 읽기 쉽게 구성한다.
- 작은 영문 라벨은 정돈된 느낌으로 표현한다.
- 전체적으로 스케치북에 그린 앱 기획서 같은 분위기를 유지한다.
- 지나치게 고급 브랜드 앱처럼 정제된 느낌보다, 기획자가 그린 선명한 흑백 모바일 시안 느낌을 우선한다.

## 9. 라인 / 테두리 스타일

모든 주요 UI 요소는 검은색 테두리를 사용한다.  
캐치캐쉬 UI의 핵심은 **삐뚤빼뚤한 손그림 외곽선**이다.

### 9.1 테두리 기본값

```txt
두께: 1.5px ~ 3px
색상: #000000
스타일: 손으로 직접 그린 듯한 slightly rough outline
모서리: 너무 둥글지 않은 직사각형 기반
정렬: 요소 위치와 크기는 정돈
```

### 9.2 적용 대상

```txt
카드
버튼
입력창
지도 박스
랭킹 카드
쿠폰 카드
팝업
바텀시트
필터 칩
상태 배지
체크박스
약관 row
```

### 9.3 손그림 라인 원칙

- 외곽선은 완벽한 직선이 아니라 약간 삐뚤고 울퉁불퉁해야 한다.
- 단, 요소의 위치와 정렬은 무너지면 안 된다.
- 카드끼리의 간격, 버튼 폭, 인풋 폭은 일정해야 한다.
- 라인이 너무 지저분해져서 가독성을 해치면 안 된다.
- UI 구조는 명확하고 정돈되어야 한다.

### 9.4 원하는 것과 원하지 않는 것

| 구분 | 설명 |
|---|---|
| 원하는 것 | 선이 비뚤다, 외곽선이 거칠다, 손으로 그린 듯하다 |
| 원하지 않는 것 | 카드 정렬이 안 맞다, 버튼 위치가 흔들린다, 입력창 폭이 제각각이다 |

핵심 문장:

```txt
삐뚤빼뚤함은 선의 질감이지, 레이아웃 붕괴가 아니다.
```

### 9.5 구현 보정 문구

화면별 지시문에 아래 문구를 함께 넣는다.

```txt
레이아웃 자체는 정돈된 모바일 앱 구조를 유지해줘.
카드, 버튼, 인풋박스, 탭, 체크박스는 정렬된 박스 형태를 유지해야 해.

하지만 각 요소의 외곽선은 완벽한 직선이 아니라,
손으로 직접 그린 듯한 약간 삐뚤고 울퉁불퉁한 스케치 라인으로 표현해줘.

구조는 정갈하게, 선은 거칠게 만들어줘.
너무 매끈한 현대 앱 UI처럼 만들지 말고,
너무 망가진 낙서처럼도 만들지 마.
```

## 10. 배경 스타일

배경은 완전한 순백보다 종이 같은 따뜻한 오프화이트 느낌으로 구성한다.

기본 배경:

```txt
#F7F5EF
```

### 10.1 배경 장식

필요한 경우 아주 흐린 스케치 장식을 사용할 수 있다.

허용 예시:

```txt
흐린 보물상자 스케치
흐린 지도 라인
작은 나뭇잎 드로잉
손그림 별 아이콘
흐린 곡선 장식
```

### 10.2 배경 장식 원칙

- 장식은 정보보다 튀면 안 된다.
- 입력 화면에서는 장식을 최소화한다.
- 지도/보물/랭킹 화면에서는 손그림 감성을 강화하는 수준으로만 사용한다.

## 11. 버튼 스타일

버튼은 검은색 또는 흰색 기반으로 구성한다.

### 11.1 Primary Button

```txt
배경: #000000
텍스트: #FFFFFF
테두리: #000000
모서리: 너무 둥글지 않은 박스형
높이: 48px ~ 56px
느낌: 마카로 칠한 듯한 강한 CTA
외곽선: 손그림처럼 약간 거친 박스 라인
```

사용 예시:

```txt
사냥 시작
사냥 합류하기
AR로 보물 찾기 시작
쿠폰 받기
문의 등록하기
저장
```

### 11.2 Secondary Button

```txt
배경: #FFFFFF
텍스트: #000000
테두리: #000000
모서리: 너무 둥글지 않은 박스형
외곽선: 손그림처럼 약간 거친 박스 라인
```

사용 예시:

```txt
정보 보기
다시 해봐
보관함으로 가기
지도에서 더 찾기
```

### 11.3 Text Button

```txt
배경 없음
텍스트: #000000 또는 #777777
작고 조용한 액션
```

사용 예시:

```txt
취소
관둬
나중에
닫기
```

### 11.4 버튼 공통 원칙

- 과한 그림자는 사용하지 않는다.
- 검은 테두리와 굵은 텍스트로 구분한다.
- Primary CTA는 화면에서 하나만 강조하는 것을 원칙으로 한다.
- 비활성 버튼은 회색 선과 회색 텍스트로 처리한다.
- Pill 버튼처럼 너무 매끈하고 둥글게 만들지 않는다.
- 버튼 형태는 박스형을 유지하되, 외곽선은 손그림처럼 삐뚤빼뚤하게 표현한다.
- 버튼의 폭과 위치는 다른 요소와 정렬되어야 한다.

### 11.5 Primary Button 구현 지시문

```txt
CTA 버튼은 검은 배경의 직사각형 버튼으로 만들어줘.
버튼 형태는 정렬된 박스지만,
외곽선과 테두리 느낌은 손으로 그린 듯 거칠고 약간 비뚤게 표현해줘.
매끈한 rounded modern button이나 pill button은 사용하지 마.
```

## 12. 카드 스타일

카드는 두꺼운 검은 테두리와 살짝 둥근 모서리를 사용한다.

### 12.1 카드 기본값

```txt
배경: #FFFFFF 또는 #F7F5EF
테두리: #000000
border-radius: 4px ~ 12px
box-shadow: 거의 없음
padding: 넉넉하게
외곽선: 손으로 그린 듯한 rough sketch border
```

### 12.2 강조 카드

중요 카드나 강조 카드에는 검은색 채움 배경을 사용할 수 있다.

사용 예시:

```txt
my record 카드
주요 CTA 카드
랭킹 요약 카드
사냥 시작 카드
```

강조 카드 스타일:

```txt
배경: #000000
텍스트: #FFFFFF
테두리: #000000
```

### 12.3 카드 원칙

- 카드 안의 정보 위계가 명확해야 한다.
- 아이콘, 제목, 보조 텍스트, 버튼 위치를 일정하게 유지한다.
- 같은 성격의 카드는 같은 형태를 유지한다.
- 카드 형태는 직사각형 기반으로 유지한다.
- 카드 외곽선은 완전한 직선이 아니라 손그림처럼 약간 비뚤고 거친 라인으로 표현한다.
- 카드끼리의 정렬, 높이, 간격은 일정하게 유지한다.

### 12.4 카드 구현 지시문

```txt
카드는 정보 정렬이 잘 된 직사각형 카드로 구성하되,
카드 외곽선은 손그림 스케치처럼 slightly rough하고 crooked한 라인을 사용해줘.
카드끼리 정렬은 맞아야 한다.
```

## 17. 입력 필드 스타일

로그인, 닉네임, 문의하기 같은 입력 화면에서는 입력 필드를 단순한 선 중심으로 구성한다.

### 17.1 입력 필드 기본값

```txt
배경: #FFFFFF
테두리: 검은색 거친 박스 라인
라벨: 작은 회색 텍스트
placeholder: #777777
focus 상태: 검은색 선 강조
형태: 가로형 직사각형 박스
```

### 17.2 화면별 적용

| 화면 | 입력 필드 형태 |
|---|---|
| 로그인 | 소셜 버튼 중심, 입력 필드 없음 |
| 닉네임/약관 | 거친 손그림 박스형 input |
| 프로필 변경 | 하단 선 또는 거친 박스형 input |
| 문의하기 | 거친 박스형 input + textarea |

### 17.3 입력 필드 원칙

- placeholder만으로 의미를 전달하지 않는다.
- label을 명확히 표시한다.
- 오류 메시지는 필드 아래에 작고 명확하게 표시한다.
- 포커스 상태는 검은 선 강조로 표현한다.
- 입력창은 완전히 매끈한 기본 input처럼 보이면 안 된다.
- 흰 배경의 가로형 직사각형 박스를 유지하되, 외곽선은 삐뚤빼뚤한 손그림 라인으로 표현한다.
- 인풋의 폭과 위치는 다른 폼 요소와 정렬되어야 한다.

### 17.4 입력 필드 구현 지시문

```txt
인풋박스는 가로형 직사각형 형태를 유지하되,
외곽선은 손그림처럼 약간 삐뚤고 거칠게 표현해줘.
흰 배경 + 두꺼운 검은 테두리.
완전한 직선 박스가 아니라,
스케치한 듯한 uneven outline을 사용해줘.
```

## 18. 체크박스 / 약관 Row 스타일

약관 동의, 필터, 선택 항목에서 사용하는 체크박스는 손그림 느낌의 작은 네모 박스로 구성한다.

### 18.1 체크박스 기본값

```txt
크기: 16px ~ 22px
배경: #FFFFFF
테두리: #000000
선 두께: 1.5px ~ 2px
형태: 손그림 느낌의 네모 박스
```

### 18.2 체크 상태

| 상태 | 표현 |
|---|---|
| 미체크 | 흰 배경 + 검은 거친 테두리 |
| 체크 | 검은색으로 칠해진 박스 또는 손그림 체크 표시 |
| 비활성 | 흐린 회색 테두리 |

### 18.3 약관 Row

- 체크박스, 약관 라벨, 우측 화살표를 한 줄에 배치한다.
- Row는 화면 좌우 여백 기준으로 정렬한다.
- 우측 화살표는 흑백 라인 아이콘으로 표현한다.
- 약관 문구 자체는 정확하게 작성한다.

### 18.4 체크박스 구현 지시문

```txt
체크박스는 작은 네모 박스 형태를 유지하되,
손으로 그린 듯한 외곽선을 사용해줘.
체크된 상태는 검게 칠한 박스 또는 거친 체크 표시로 표현해줘.
```


## 19. 지도 스타일

지도 화면은 실제 컬러 지도가 아니라 흑백 스케치 지도 이미지 느낌으로 표현한다.

### 18.1 지도 스타일

```txt
연필로 그린 듯한 도로 라인
흑백 위치 핀
종이 질감 배경
검은 테두리 지도 박스
단순한 검은 핀 또는 원형 마커
```

### 18.2 지도 원칙

- 디자인 시안에서는 실제 네이버 지도처럼 컬러풀하게 표현하지 않는다.
- 보물 위치, 현재 위치, 탐색 반경은 흑백 라인과 패턴으로 구분한다.
- 지도 박스는 굵은 검은 테두리로 감싼다.

- 귀엽지만 서비스 앱에 어울리는 정도로 표현한다.
- 너무 아동용 캐릭터처럼 보이면 안 된다.
- 실물 사진 스타일은 사용하지 않는다.

```txt
바코드 영역: 흑백 라인 바코드

```

## 24. 구현 방식 기준

캐치캐쉬는 이미지만 에셋으로 분리하고, UI 구조는 CSS/컴포넌트로 구현한다.

### 24.1 이미지 에셋으로 분리할 것

```txt
로고 심볼
브랜드 일러스트
캐릭터 이미지
보물상자 이미지
쿠폰/빈 상태 일러스트
지도 마커 이미지가 필요한 경우
```

### 24.2 CSS/컴포넌트로 구현할 것

```txt
카드 외곽선
버튼 외곽선
입력창 외곽선
체크박스
필터 칩
탭바
팝업 박스
배경색
단순 배경 라인 장식
텍스트
로딩바
```

### 24.3 손그림 외곽선 구현 메모

실제 개발 시 손그림 느낌은 아래 방식으로 구현한다.

```txt
CSS border
border-radius
outline 또는 pseudo-element
약간의 rotate/translate
box-shadow 대신 보조 border
SVG 에셋은 꼭 필요한 경우에만 사용
```

단, 화면별로 외곽선을 이미지로 제각각 만들지 않는다.

```txt
컴포넌트는 공통화하고
손그림 느낌은 CSS 스타일 규칙으로 통일한다.
```

## 29. 바이브코딩 지시문에 반드시 포함할 문장

각 화면별 바이브코딩 지시문 마지막에 아래 문장을 반드시 붙인다.

```txt
이 화면 디자인에 필요한 이미지 에셋을 반드시 분리해서 정리해줘.
단, 카드/버튼/인풋/체크박스/탭/팝업 외곽선은 이미지 에셋으로 만들지 말고 CSS 컴포넌트로 구현할 수 있게 디자인해줘.

각 이미지 에셋은 asset_name, asset_type, format, usage_screen, recommended_size, description 형태의 표로 작성해줘.

에셋명은 반드시 아래 규칙을 따라줘.
{category}_{name}_{state}_{size}.{ext}

또한 이 화면에서 공통 컴포넌트로 분리할 수 있는 요소도 함께 정리해줘.

중요:
구조는 정갈하게, 선은 거칠게.
삐뚤빼뚤함은 선의 질감이지 레이아웃 붕괴가 아니야.
```

## 31. 화면별 적용 메모

### 29.1 스플래시

- 중앙 로고/심볼 중심
- 흑백 보물상자/지도/위치 핀 스케치 사용
- 버튼 없음
- 하단 로딩 텍스트 가능
- 말투는 약하게 적용

### 29.2 로그인

- 로고와 소셜 로그인 버튼 중심
- 카카오/구글/애플 버튼도 흑백 테두리 스타일로 표현
- 실제 브랜드 컬러를 과하게 사용하지 않음
- 문구는 약간 도발적으로 사용 가능

예시:

```txt
들어와. 보물은 기다려주지 않아.
카카오로 기어들어가기
구글로 시작하기
```

단, 실제 서비스에서 과하면 버튼 문구는 순화한다.

### 29.3 닉네임/약관

- 레퍼런스처럼 강한 타이틀 사용
- 예: `널 뭐라 부르냐?`
- 약관 문구는 명확하고 법적 의미를 훼손하지 않음

### 29.4 홈

- 지도 미리보기, 근처 보물, 최근 사냥 기록 중심
- 굵은 검은 CTA 사용
- 하단 탭바 포함
- 예: `근처에 뭐 좀 숨겨놨다`

### 29.5 지도

- 컬러 지도 대신 흑백 스케치 지도 표현
- 보물 마커와 내 위치 마커는 단순 라인 아이콘 사용
- 예: `내 위치`, `반경 500m`, `근처 보물`

### 29.6 AR

- 카메라 화면도 디자인 시안에서는 흑백 프레임과 보물상자 오브젝트 중심으로 표현
- 실제 AR 기능 설명보다 조작 UI가 명확해야 함
- 예: `눌러. 네 거면 열릴 거야.`

### 29.7 보관함/쿠폰

- 쿠폰 카드는 흑백 테두리 카드
- 사용됨/만료는 회색/점선/흐림으로 구분
- 쿠폰 코드 팝업은 코드번호와 바코드 가독성을 최우선
- 예: `네 전리품이나 확인해`

### 29.8 프로필

- 실물 사진 금지
- 제공 캐릭터와 배경만 사용
- 캐릭터는 흑백 또는 저채도 스케치 아바타
- 예: `널 이렇게 부르면 되냐?`

### 29.9 문의하기 / 문의 내역 / 문의 상세

문의 영역은 단일 작성 화면이 아니라 아래 3개 화면으로 구분한다.

```txt
/support = 문의 내역 리스트
/support/[inquiryId] = 문의 상세 및 관리자 답변 확인
/support/new = 문의 작성
```

- 내프로필에서 `문의하기` 버튼을 누르면 `/support` 문의 내역 리스트가 먼저 나온다.
- 리스트 화면에서는 사용자가 등록한 문의 제목, 날짜, 처리 상태를 카드로 보여준다.
- 리스트 하단 `문의하기` CTA를 누르면 `/support/new` 문의 작성 화면으로 이동한다.
- 문의 카드를 누르면 `/support/[inquiryId]` 문의 상세 화면으로 이동한다.
- 문의 상세에서는 사용자 문의와 관리자 답변을 한 화면에서 보여준다.
- 관리자 답변이 등록되면 알림함에 `문의 답변 도착` 알림이 생성될 수 있다.
- 별도의 답변함 화면은 MVP 범위에서 만들지 않는다.
- 예: `뭔 일 있었냐?`, `뭔 일인지 말해봐`, `던져놓기`, `알았다 (뒤로가기)`
