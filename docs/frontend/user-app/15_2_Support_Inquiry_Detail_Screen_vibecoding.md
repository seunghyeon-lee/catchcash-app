# 15_2_Support_Inquiry_Detail_Screen

## 1. 화면 개요

- 화면명: 문의 상세 화면
- 경로: `/support/[inquiryId]`
- 목적:
  - 사용자가 등록한 문의 내용과 관리자 답변을 한 화면에서 확인하는 화면
  - 문의 처리 상태(`읽는 중`, `해결됨`)를 명확히 보여주는 화면
  - 확인 후 문의 리스트 화면으로 돌아갈 수 있는 화면
- 진입 경로:
  - `/support` 문의 리스트 화면에서 문의 카드 클릭
  - 알림함의 `문의 답변 도착` 알림 클릭
- 이전/다음 경로:
  - 하단 `알았다 (뒤로가기)` 버튼 클릭 → `/support`
  - 상단 뒤로가기 클릭 → 이전 화면 또는 `/support`

---

## 2. 화면 정책

- 문의 상세 화면은 문의 작성 화면이 아니다.
- 사용자가 이미 등록한 문의와 관리자 CMS에서 작성한 답변을 확인하는 화면이다.
- 사용자의 문의 내용은 상단 카드에 표시한다.
- 관리자 답변은 하단 카드에 표시한다.
- 답변이 등록된 문의는 `해결됨` 상태로 표시한다.
- 답변이 아직 없는 문의는 `읽는 중` 상태로 표시한다.
- 답변이 없는 경우 관리자 답변 카드에는 대기 안내 문구를 표시할 수 있다.
- 상단 GNB와 하단 탭바는 공통 컴포넌트를 사용한다.
- 본 화면 MD에서는 공통 아이콘/공통 탭 에셋을 신규 정의하지 않는다.
- 실제 API/Supabase 연동 전까지는 Mock Data 기준으로 구현한다.

---

## 3. 레이아웃 구조

### 3-1. 상단 영역

- 공통 상단 GNB 사용
- 구성:
  - 뒤로가기
  - 서비스명 `뭐라카노 답변`
  - 알림 아이콘
  - 도움말 아이콘
  - 설정 아이콘
- 상단 GNB 아이콘은 공통 에셋을 사용한다.

### 3-2. 상태 배지 영역

- 화면 상단 중앙에 문의 상태 배지를 표시한다.
- 상태에 따라 아래 배지를 사용한다.
  - 해결됨
  - 읽는 중
- 상태 배지는 문의 상세 화면의 현재 처리 상태를 가장 먼저 인지시키는 역할을 한다.

### 3-3. 사용자 문의 카드 영역

- 사용자가 등록한 문의 내용을 표시한다.
- 카드 내부 구성:
  - `내가 쓴 거` 라벨
  - 작성일
  - 사용자 아이콘
  - 문의 제목 또는 문의 본문
- 텍스트는 코드 텍스트로 구현한다.
- 카드 프레임은 전용 에셋을 사용한다.

### 3-4. 관리자 답변 카드 영역

- 관리자 CMS에서 등록한 답변 내용을 표시한다.
- 카드 내부 구성:
  - `관리자의 대답` 라벨
  - 관리자 답변 아이콘
  - 답변 본문
- 답변이 없는 경우에는 `아직 관리자가 읽는 중이야.` 등의 대기 문구를 표시할 수 있다.
- 텍스트는 코드 텍스트로 구현한다.
- 카드 프레임과 헤더 라벨은 전용 에셋을 사용한다.

### 3-5. 하단 CTA 영역

- 하단에 `알았다 (뒤로가기)` 버튼을 배치한다.
- 클릭 시 `/support` 문의 리스트 화면으로 이동한다.

### 3-6. 하단 탭바

- 공통 하단 탭바 사용
- 현재 화면은 `내정보` 탭 활성 상태로 본다.

## 6. 인터랙션 정의

### 6-1. 상단 뒤로가기

- 클릭 시 이전 화면으로 이동한다.
- 이전 화면 정보가 없을 경우 `/support`로 이동한다.

### 6-2. 하단 CTA 버튼

- `알았다 (뒤로가기)` 클릭 시 `/support` 문의 리스트 화면으로 이동한다.

### 6-3. 상태별 표시

#### 해결됨

- 상태 배지: `ui_badge_support_status_resolved_black_rough_default.svg`
- 사용자 문의 카드 표시
- 관리자 답변 카드 표시

#### 읽는 중

- 상태 배지: `ui_badge_support_status_reading_white_rough_default.svg`
- 사용자 문의 카드 표시
- 관리자 답변 카드에는 대기 문구 표시 가능

예시 대기 문구:

- `아직 읽는 중이야. 답변 오면 알림으로 알려줄게.`

### 6-4. 알림 연계

- 관리자 CMS에서 답변 등록 시 알림함에 `문의 답변 도착` 알림이 생성될 수 있다.
- 알림 클릭 시 `/support/[inquiryId]` 상세 화면으로 이동한다.

## 7. 상태값 정의

프론트 표시 기준 상태값:

- `reading`
  - 표시명: `읽는 중`
  - 의미: 관리자가 문의를 확인 중이거나 답변이 아직 등록되지 않은 상태
- `resolved`
  - 표시명: `해결됨`
  - 의미: 관리자 답변이 등록되었거나 문의 처리가 완료된 상태

## 9. 구현 기준

- 상단 GNB는 공통 컴포넌트를 사용한다.
- 하단 탭바는 공통 컴포넌트를 사용한다.
- 본 화면에서는 상세 화면 전용 카드/배지/버튼 프레임만 신규 에셋으로 사용한다.
- 텍스트는 모두 코드 텍스트로 구현한다.
- 에셋 내부에 텍스트를 포함하지 않는다.
- 모바일 WebView 기준으로 구현한다.
- 최대 너비는 기존 프로젝트 공통 기준(`max-width: 480px`)을 따른다.
- 실제 API/Supabase 연동 없이 Mock Data 기반으로 우선 구현한다.
- `/support` 문의 리스트 화면에서 상세로 진입할 수 있도록 라우팅을 고려한다.

---

## 10. 개발 메모

- 본 화면은 `/support` 리스트 화면의 후속 상세 화면이다.
- MVP에서는 상세 화면을 별도 route(`/support/[inquiryId]`)로 구성하는 것을 권장한다.
- 답변함 화면은 별도로 만들지 않는다.
- 사용자는 알림 또는 문의 리스트에서 문의 상세 화면으로 진입한다.
- 관리자 답변이 등록되면 상태가 `resolved`로 변경되고 상세 화면에서 답변을 확인할 수 있다.
